# Audit log

Incidents worth a permanent record: what broke, how it was actually caught, and what changed as a result. Not a changelog — see git history for that.

## node_modules drift silently invalidated local CI verification (2026-08-16)

**What happened.** A commit that added `eslint-plugin-jsx-a11y` and `eslint-plugin-react-hooks` alongside an already-current `eslint@^10.3.0` was pushed to `main`. It had been verified locally beforehand — lint clean, tests passing, build succeeding. Both GitHub Actions and Vercel's production deploy failed on it immediately, at the dependency install step, before running anything that had been "verified."

**Root cause.** `eslint-plugin-jsx-a11y@6.10.2` declares a peer dependency on `eslint@^3` through `^9` — it has never published a version whose peer range includes ESLint 10. `npm ci` (strict, no auto-resolution) rejects that outright. `npm install`, run repeatedly over the course of local development, does not reject it the same way and had been silently keeping a local `node_modules` tree that no longer matched what the committed lockfile would actually produce. Every local "lint passes" and "tests pass" check before the push was run against that drifted tree, not against what a fresh clone would get.

**How it surfaced.** Not from a careful audit — from the actual failures: a red GitHub Actions run, and separately, a real Vercel production deploy error pasted directly from the user's own failed build log. Only after both had already happened did a genuine `rm -rf node_modules && npm ci` get run for the first time. That single command reproduced the exact ERESOLVE error both platforms had hit, and separately surfaced 80 real `eslint-plugin-react-hooks@7.x` lint errors that had never appeared in any prior local run — not because the code had changed, but because the linter had never actually run with the dependency tree the lockfile described.

**The fix, and why it was verified the way it was.** `--legacy-peer-deps` would have made `npm ci` pass by disabling strict peer-dependency checking for the entire install, not just the one known-stale declaration. Used instead: a narrow `overrides` entry in `client/package.json` that resolves only `eslint-plugin-jsx-a11y`'s `eslint` peer against the project's actual installed version. Because this fix lives in `package.json` rather than being baked into the lockfile, it needed a positive test, not just an install that happened to succeed: the same lockfile, with the override stripped from `package.json`, was fed to an isolated `npm ci` in a clean directory with no cached `node_modules`. It reproduced the original ERESOLVE failure exactly. Put back, it installed cleanly. That's what "verified" means here — not "the install succeeded once," but "the install fails without this specific change and succeeds with it, checked in isolation from any local cache."

The first attempt at writing the fixed lockfile (`rm -rf package-lock.json && npm install`) was correct but imprecise: it re-resolved the entire dependency tree against the current registry, pulling in 64 unrelated version bumps as a side effect of full regeneration. Isolated down to a 5-line diff using `git checkout <base> -- package-lock.json && npm install --package-lock-only`, which updates only what the override actually requires instead of re-resolving everything that happens to still be within range.

**The lesson.** A local "all green" result only means what it claims to mean if the environment producing it matches what CI/production will actually use. `node_modules` that has been through enough `npm install` cycles over a long working session can drift from the committed lockfile without any single command signaling that it happened — there's no warning, no diff, nothing to notice. The only way to trust a local check is to occasionally throw the local state away and rebuild it exactly the way a fresh clone would: `rm -rf node_modules && npm ci`, not `npm install`. Every verification claim made against a long-lived local install carries this same risk until it's been confirmed against a clean one.
